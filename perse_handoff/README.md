## 2. 制作方法（なぜ自作レンダラーなのか）

- 作業していた環境では Blender（bpy）がインストールできなかった（パッケージ取得がプロキシで拒否された）。
- そのため **C++ で自作した物理ベースのパストレーサー（`pt.cpp`）** で光の反射を計算して絵を作り、
  Python で **ノイズ除去と写真風の色仕上げ（`post2.py`）** をしている。
- 部屋・家具・素材・カメラは **Python スクリプト（`kyuke.py` など）にコードで記述** している。

> Claude Code（自分の PC）では Blender が使える可能性が高い。より高品質にする場合は、
> 「`kyuke.py` の形状・素材・カメラを Blender（Cycles）に移植して」と頼むのが進化の近道（→ 9章）。

### 処理の流れ

```
kyuke.py（部屋・家具・素材・照明・カメラ）
   │  python3 kyuke.py <view> W H SPP out/<view>.txt
   ▼
シーンファイル（テキスト）
   │  ./pt out/<view>.txt out/<view>_f
   ▼
_col / _alb / _nrm / _dep の .bin（色・アルベド・法線・深度）
   │  python3 post2.py out/<view>_f W H out.jpg [露出]
   ▼
JPG（ノイズ除去 → ACES トーンマップ → ブルーム・周辺減光・粒子）
```

## 4. 動かし方

必要なもの：C++ コンパイラ、`python3`、`numpy`、`opencv-python`

```bash
pip3 install -r render/requirements.txt
cd render
./build.sh                      # 初回だけ（run_*.sh も pt が無ければ自動でビルドする）

./run_kyukei.sh                 # 休憩室 3面（1440×900, 128spp）→ render/out/kyukei_*.jpg
./run_kyukei.sh 480 300 24      # 試し描き（数十秒/面）
./run_salon.sh                  # 美容室 4面（1440×900, 160spp）
```

- 本番画質は 2コアのマシンで **1面あたり約20分**。コア数に比例して速くなる。
- **macOS の注意**：標準の clang は OpenMP（並列計算）に対応していない。`build.sh` は Homebrew の gcc や libomp があれば自動で使い、
  無ければ1スレッド版でビルドする（動くが数倍遅い）。速くするには `brew install libomp`（または `brew install gcc`）を入れてから `rm pt && ./build.sh`。
- 作業のコツ：**低解像度（480×300, 24spp）で確認 → OK なら本番** の順にする。
- 露出：`post2.py` は自動露出。休憩室は自動値 × 0.85 で仕上げている（`run_kyukei.sh` に記述済み）。

### 4.1 Blender（Cycles）版（2026-11 追加・比較検討中）

`blender/` に、`kyuke.py` のシーンをそのまま Blender（Cycles）で描くスクリプトを追加した。
形・素材・照明・画角は `kyuke.py` から直接読み込むので、**`kyuke.py` を直せば両方のレンダラーに反映される**。

```bash
pip3 install bpy numpy opencv-python      # bpy = Blender 本体の Python 版（Python 3.13 用）
cd blender
./run_kyukei_cycles.sh 480 300 32         # 試し描き（約30秒/面・4コア）
./run_kyukei_cycles.sh                    # 本番 1440×900（→ blender/out/kyukei_<view>_cycles.jpg）
./run_kyukei_cycles.sh 1440 900 128 north # 1面だけ
```

- `kyuke_cycles.py`：シーンを組み立てて Cycles でレンダリング（ノイズ除去は OIDN）。`SAVE_BLEND=1` を付けると `.blend` も保存するので、Blender で開いて手で調整できる。
- `post_cycles.py`：`post2.py` と同じ写真風の仕上げ（ACES・ブルーム・周辺減光・粒子）。露出は自動値 × 0.85。
- 照明の強さは `pt.cpp` と同じ明るさになるよう換算済み（`LIGHT_SCALE`）。
- 外の空（sky）のパネルが Cycles では実際に部屋を照らすため、窓際が自作レンダラーより少し明るくなる。
- **デザイン案（バリエーション）**：`render/variants.py` に、レイアウト（位置・大きさ）を変えずに仕上げ・色・光色だけを変える案を置く。
  `VARIANT=cafe ./run_kyukei_cycles.sh` → `out/kyukei_<view>_cycles_cafe.jpg`。
  - `cafe`「Warm Oak & Smoke」：天井を温かい薄グレージュ、造作をスモークドオーク、テーブルは明るいオーク（マット）、ソファ後ろの木目クロスをウォールナット調、
    ハイカウンター天板を石目（テラゾー調）、クッションにくすんだ青緑とテラコッタ、キッチン・前室のダウンライトを温白色 3500K（席まわりは電球色のまま）。**提案段階・未承認**。
- 面がぴったり重なった家具（棚板と側板など）は、Cycles では黒い筋になる。それを防ぐため、部屋の外殻以外の箱を 0.1〜0.9mm だけ内側に縮めている（見た目には影響しない）。

## 5. レンダラー（pt.cpp）の仕様

### 座標系
- 単位はメートル。**y が上**。カメラの yaw は「0 = −z 方向を向く、π/2 = +x 方向」。

### シーンファイルの書式（1行1要素）

| 行 | 書式 |
|---|---|
| 素材 | `mat r g b type tex ks ex er eg eb bump axis` |
| 箱 | `box cx cy cz hx hy hz R[9] mat flags` |
| 角丸の箱 | `rbx cx cy cz hx hy hz r R[9] mat flags`（SDF で描画） |
| 円柱 | `cyl x0 y0 z0 x1 y1 z1 r mat flags` |
| 楕円体 | `ell cx cy cz M[9] Rmax mat flags` |
| 照明 | `light px py pz dx dy dz Ir Ig Ib inner outer rad upFrac`（スポット／点光源） |
| カメラ | `cam x y z yaw fovh shiftX shiftY W H spp` |
| 背景光 | `env r g b`（窓の外に抜けた光線の明るさ） |

- `R[9]` は回転行列（行優先）。列が箱のローカル軸。
- `flags`：bit1 = 影を落とさない、bit2 = クリップ対象外（部屋の外殻）。
- 素材 `type`：0 拡散＋Phong 反射 / 1 鏡 / 2 ガラス / 3 半透明 / 4 金属
- 素材 `tex`：0 なし / 1 フローリング / 2 腰板 / 3 塗り壁・漆喰調 / 4 木目 / 5 絵 / 6 市松タイル / 7 レザー / 8 布・紙
- `axis`：木目やフローリングの向き。**フローリングは `axis=2` で z 方向（部屋の長手）に張る**（休憩室で追加）。
- ホタル状のノイズ抑制のため、1サンプルの明るさを 14 で頭打ちにしている。

### Python 側の補助関数（kyuke.py 内）
- `box(x1,y1,z1,x2,y2,z2,mat)` 軸に沿った箱 / `obox(中心,半径,回転,mat)` 回転した箱
- `rr(中心,半径,mat,r=角丸)` 角丸の箱 / `cyl(p0,p1,r,mat)` / `ell(中心,半径xyz,回転,mat)`
- `downlight(x,z,I,...)` ダウンライト（器具の形と光をセット）
- `leaves()` / `plant()` 観葉植物、`cafechair()` 椅子、`roundtable()` 丸テーブル、`stool()` ハイスツール
- `setg('名前')` 以降の要素をグループ化。`VIEWS` の `drop` に入れたグループはその画角で非表示（カメラ手前の邪魔物を消す用）。
- `view(カメラx, カメラz, 注視点x, 注視点z, 画角, drop, cy=目線高さ)` で画角を定義。

## 8. 既知の課題・制約

- 自作レンダラーのため、Blender/Cycles と比べると：ソフトな影の質、布やガラスの質感、間接光のノイズ（低サンプル時）に限界がある。
- 自販機・テレビ・小物はブランドロゴなしの汎用形状。
- 寸法は図面の縮尺読み取りを含む（特に部屋の奥行 11.8m、L字の段差位置）。CAD データがあれば正確にできる。
- `pt.cpp` の先頭コメントは美容室用のまま（機能は共通）。

## 9. Claude Code で進化させる方向（提案）

1. **Blender（Cycles）への移植**：`kyuke.py` の形状・素材・ライト・カメラを bpy スクリプトに変換 → GPU レンダリング、実写に近い質感、OIDN デノイズ。最も効果が大きい。
2. **CAD／DXF から壁・建具を自動生成**：図面データがあれば寸法の読み取り誤差がなくなる。
3. **実物の家具・建材の再現**：エスティコなどメーカーの 3D データ（あれば）やテクスチャ画像の利用。
4. **バリエーション出し**：床・クロス・ソファ生地の色違いを一括でレンダリングして比較表にする。
